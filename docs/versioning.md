# Версионирование FogMap

Единственный источник базы версии — файл `version` в корне (`MAJOR.MINOR.PATCH`,
одна ASCII-строка, без BOM). Полная версия сборки вычисляется в
`app/build.gradle.kts`: `<base>.<git-count>-g<sha>[-dirty-<TS>]`,
`versionCode` = `git rev-list --count HEAD`. Агент **никогда** не правит
версию в gradle — только файл `version`.

## Классификация (по наивысшему уровню среди изменений сессии/коммита)

- **MAJOR (`X.0.0`)** — ломающая совместимость: миграция БД с потерей данных,
  смена схемы хранения/формата треков, смена `minSdk`/карты SDK/архитектуры,
  удаление фичи. Обнуляет MINOR и PATCH.
- **MINOR (`x.Y.0`)** — новая видимая фича или поведение: новый экран,
  режим трекинга, эко-губернатор, импорт/экспорт, новая метрика статистики,
  изменение логики открытия тумана. Обнуляет PATCH.
- **PATCH (`x.y.Z`)** — фикс без новых фич: краш, GPS-фильтр, UI-правка,
  производительность, тексты, подпись/сборка для пользователя.
- **NO_BUMP** — бамп НЕ нужен: только доки/спеки (`docs/`, `openspec/`,
  `*.md`), только тесты без поведения, чистый рефактор, CI/сборка без
  изменения продукта, WIP внутри незаархивированного change.

Примеры из истории проекта:
- эко-губернатор ACTIVE/STANDBY/BURST, wake-balance-parking, smooth-fog-zoom — MINOR;
- фикс SIGABRT тумана, `gitDirty всегда true`, TrustEngine cap — PATCH;
- правки `docs/sessions.md`, `decisions.md`, спек без кода — NO_BUMP.

## Когда принимать решение (обязательно)

1. **Начало сессии:** прочитать `version` и верх `CHANGELOG.md`.
2. **Конец сессии / перед коммитом / при архивации OpenSpec-change:**
   посмотреть `git status --porcelain` + `git diff --stat`, классифицировать,
   принять ровно одно решение: MAJOR / MINOR / PATCH / NO_BUMP.
3. **Максимум один бамп за сессию.** Не бампить дважды за одни и те же
   невыпущенные изменения. Не бампить ради грязной сборки (`-dirty-`
   суффикс — не повод). WIP внутри change не бампится — решение
   принимается при архивации change.

## Как бампить

1. Записать новую базу в `version` (например `1.1.0`).
2. Добавить секцию в `CHANGELOG.md` (дата + что вошло + уровень).
3. В `docs/sessions.md` в записи сессии — строка `Версия: ...`
   (например `Версия: 1.0.0 → 1.1.0 (MINOR, эко-губернатор)` или
   `Версия: без изменений (1.0.0, только доки)`).
4. В сообщении коммита упомянуть версию (например `... + версия 1.1.0`).
5. Проверить: `python scripts/check-version.py`
   (формат semver, соответствие CHANGELOG, подсказка классификации).

## Запреты

- Не держать версию в двух местах (только файл `version`).
- Не бампить «на всякий случай» и не спрашивать владельца ради бампа —
  решение принимает агент по этой таблице.
- Не коммитить APK из `dist/` (уже в `.gitignore`).
