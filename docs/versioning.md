# Версионирование FogMap

Единственный источник базы версии — файл `version` в корне (`MAJOR.MINOR.PATCH`,
одна ASCII-строка, без BOM). Полная версия сборки вычисляется в
`app/build.gradle.kts`: `<base>.<git-count>-g<sha>[-dirty-<TS>]`,
`versionCode` = `git rev-list --count HEAD`. Агент **никогда** не правит
версию в gradle — только файл `version`.

## Модель: бамп только на релизе APK (с 2026-09-24)

`version` = база **последнего опубликованного релиза** (git-тег `vX.Y.Z`,
ассеты в `dist/archive/`). Между релизами файл `version` НЕ трогается:
всё новое копится в секции `## [Unreleased]` в `CHANGELOG.md`.

Причина изменения процесса: за два дня (22–24.09) набежало три нерелизных
«версии» (1.6.0, 1.7.0, 1.7.1) — номера перестали что-то значить. Теперь
один бамп = один реально выпущенный APK; версии 1.6.0/1.7.0/1.7.1 отменены
и свёрнуты в `## [Unreleased]` вместе с последующими правками.

### Обычная сессия (без релиза)

1. Начало сессии: прочитать `version` + верх `CHANGELOG.md` (должен быть `## [Unreleased]`).
2. Конец сессии / коммит / архивация change: `git status --porcelain` + `git diff --stat`.
   - есть пользовательское изменение (код, поведение, доки о нём) → добавить пункт в `## [Unreleased]`;
   - только доки/спеки/тесты/чистый рефактор/CI → в `CHANGELOG` ничего не писать;
   - **файл `version` не менять**, версионные секции не создавать.
3. Строка `Версия:` в `docs/sessions.md` → `без бампа (в Unreleased; бамп на релизе)`.

### Релиз (`build-apk.bat release` → `release.ps1`)

1. Классифицировать **всё** из `## [Unreleased]` по наивысшему уровню:
   - **MAJOR (`X.0.0`)** — ломающее совместимость: миграция БД с потерей данных,
     смена схемы хранения/формата треков, смена `minSdk`/карты SDK/архитектуры,
     удаление фичи.
   - **MINOR (`x.Y.0`)** — новая видимая фича или поведение: новый экран,
     режим трекинга, эко-губернатор, импорт/экспорт, новая метрика статистики,
     изменение логики открытия тумана.
   - **PATCH (`x.y.Z`)** — в накопленном только фиксы: краш, GPS-фильтр,
     UI-правка, производительность, тексты, сборка.
2. Записать новую базу в `version`, свернуть `[Unreleased]` в `## [x.y.z] — дата (УРОВЕНЬ)`.
3. `python scripts/check-version.py` (exit 0) → коммит с упоминанием версии →
   `release.ps1` публикует тег `vX.Y.Z` и ассеты.

### Примеры

- Сессия дописала фикс → пункт в `## [Unreleased]`, `version` не трогаем.
- Выпущен APK с накопленными фичами и фиксами → MINOR: `1.5.2` → `1.6.0`,
  `[Unreleased]` свёрнут в `## [1.6.0]`.
- Чистые доки/спеки/тесты → в `CHANGELOG` ничего, `version` не трогаем.

## Запреты

- Не бампить `version` вне релиза (бамп и есть релиз).
- Не держать версию в двух местах (только файл `version`).
- Не бампить «на всякий случай» и не спрашивать владельца ради бампа —
  правило применяется агентом по этой странице.
- Не коммитить APK из `dist/` (уже в `.gitignore`).
