## Context

Текущая архитектура: materialized counters в `counters` (key/value), инкремент в `FogRepository.appendPoints`. Нет таблицы achievements. `docs/vision.md` фиксирует «без геймификации» (2026-09-14) с оговоркой «если появится — отдельным change». Мотивация — proposal.md. Зависимость: change `add-region-progress`.

## Goals / Non-Goals

**Goals:**
- Room-таблица `achievements` для разблокированных наград
- Триггеры: % региона, площадь, серии дней
- Экран достижений + уведомления
- Обновление vision.md

**Non-Goals:**
- Онлайн/глобальные leaderboard'ы
- Анимации/звуки наград
- Ачивки для друзей (change `add-friends`)
- Экспорт achievements

## Decisions

**1. Хранение: только разблокированные**
- Решение: в БД — только unlocked (id, unlocked_at). Список всех определений — Kotlin constants.
- Альтернатива: хранить все + флаг — избыточно, определения статичны.

**2. Триггеры: inline vs отдельный сервис**
- Решение: `AchievementChecker` вызывается из `appendPoints` после инкремента counters (или из UI при чтении — зависит от требований к уведомлениям).
- Уточнение: для тостов нужен вызов в момент открытия → inline в транзакции (после commit) или отдельная coroutina.

**3. Серия дней: как считать**
- Решение: новый counter `streak_days` (текущая серия) + `streak_days_best` (рекорд). Обновление при `startDayChunk`.
- Альтернатива: пересчёт из истории — дорого, ломает materialized-подход.

**4. UI: отдельный экран**
- Решение: `AchievementsScreen`, доступен из BottomBar или Stats.
- Группировка: «Регионы», «Площадь», «Серии».

**5. Уведомления**
- Решение: Snackbar/Toast при разблокировке (в пределах сессии). Push-уведомления — вне скоупа (нет фона для этого).

## Risks / Trade-offs

- [Vision conflict] → Явное обновление vision.md в задачах change.
- [Производительность триггеров] → Проверка только при инкременте, не в цикле рендера.
- [Серии дней: таймзона] → Использовать локальную дату устройства.
- [Зависимость от region-progress] → Процентные триггеры требуют региональных counters.

## Migration Plan

1. Миграция БД: добавить таблицу `achievements` (v6→v7).
2. Добавить `AchievementChecker` + константы определений.
3. Расширить `streak`-логику в `TrackRepository.startDayChunk`.
4. Rollback: миграция добавляет таблицу, revert безопасен.
