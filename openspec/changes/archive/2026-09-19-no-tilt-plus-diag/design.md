## Context

См. `proposal.md` (Why): шторм `CAMERA` 300+ событий/сек с `tilt 48–60`, самоподдерживающаяся петля возврата tilt через `map.move()` с анимацией 0.3с, UI молчит 85+ секунд. Текущее состояние кода: `MapScreen.kt:219-246` — `CameraListener` на каждое событие пишет Compose-state и при `tilt > 1` стреляет `map.move(tilt=0)`; флаг `snappingTilt` сбрасывается синхронно и от асинхронной анимации не защищает. Tilt-жест в SDK включен (настроек жестов в коде нет — проверено поиском). Диагностика (`DevCameraStats`, `DevRenderStats`, `DevPerfMonitor`) пишет только dalvik-heap, числа через `String.format` без локали (запятые при русской локали). `build-apk.bat` собирает только `assembleRelease` (`ru.fogmap`, не debuggable — `run-as` недоступен).

## Goals / Non-Goals

**Goals:**
- Tilt как явление исчезает: ни жест, ни состояние, ни корректирующая анимация.
- Диагностика видит нативную память и штормы без роста объема лога (только пороговые W-события).
- Расследование без рук пользователя: JSONL доступен через `adb run-as` на дебаг-сборке.

**Non-Goals:**
- Не трогаем rotate-жест, pinch-зум, пан, компас и сброс azimuth.
- Не меняем рендер тумана (агрегаты показали 0.3–2.6 мс — невиновен).
- Не вводим дросселирование `CameraListener`/`remember` — после отключения tilt шторму неоткуда взяться; дроссель только если шторм воспроизведется без tilt.
- Не публикуем дебаг-сборку: `ru.fogmap.dev` только для ручной установки владельцем.

## Decisions

- **Гасить жест в SDK (`map.isTiltGesturesEnabled = false` при создании карты), а не фильтровать в слушателе.** Альтернатива — игнорировать события с `tilt != 0` в `CameraListener`: отвергнута, потому что MapKit все равно гоняет анимацию наклона и шлет сотни событий/сек, нагрузка на UI-поток остается. Выключение в источнике убирает и события, и анимацию.
- **Удалить ветку возврата tilt целиком (вместе с `snappingTilt`), а не чинить ее дебаунсом.** Альтернатива — дебаунс/флаг «возврат летит»/возврат без анимации: отвергнута, потому что при выключенном жесте ветка недостижима (`tilt` всегда 0), а мертвый код с `map.move()` внутри колбэка — это будущая петля. Программные `move()` (кнопки «Где я», компас) продолжают задавать `tilt=0` явно.
- **Оставить `tilt`-поля в `CAMERA`-агрегате как сторожевой инвариант.** Если tilt снова станет ненулевым (регрессия, обновление SDK), это будет видно в существующем логе без нового кода.
- **Нативный heap через `Debug.getNativeHeapAllocatedSize()` в 10-секундный `PERF`-агрегат (поле `native_heap_mb`), плюс `Debug.MemoryInfo` только при W-событии.** Альтернатива — `dumpsys`/профилировщик: отвергнута, нужен непрерывный ряд в том же таймлайне, а не разовый снимок. `GL mtrack` отдельной строкой не тянем — виден через рост натива.
- **Порог шторма 60 событий/сек.** Наблюдалось 300+/сек в петле; обычный активный жест — десятки событий/сек. Порог отделяет норму от патологии с запасом, ложные срабатывания маловероятны. Счетчик исходящих `move()` — примитив-инкремент в месте вызова, строка собирается в агрегаторе (правило «ноль строк в горячем пути» сохраняется).
- **`Locale.US` во всех диагностических `String.format`.** Альтернатива — хранить числа как `Double` без форматирования: отвергнута, формат `%.1f` нужен для компактности лога; фиксированная локаль дешевле и чинит JSON-парсинг.
- **Режим `debug` в `build-apk.bat`, релиз по умолчанию без изменений.** `assembleDebug` без `-PtargetAbis` (эмуляторный x86_64 не вырезаем), выход `dist/FogMap-debug-latest.apk` + архивная копия. Пакет `ru.fogmap.dev` ставится рядом с релизом, данные не пересекаются. Альтернатива — собирать дебаг прямым вызовом `gradlew`: отвергнута, владельцу удобен один батник с `install`.

## Risks / Trade-offs

- [Риск] Обновление MapKit переименует/уберет флаг жеста → Митигация: сборка упадет на этапе компиляции (fail-fast), сторожевой `tilt` в логе покажет регрессию в поле.
- [Риск] Пользователь привык к наклону (вид «перспектива») → Митигация: вид сверху — требование продукта (`map-render`), наклон противоречил спеку с самого начала; принято владельцем.
- [Риск] `Debug.getNativeHeapAllocatedSize()` считает не весь GL → Митигация: нам нужен тренд роста, а не точный побайтовый учет; для точного разбора остается `dumpsys meminfo`.
- [Риск] Дебаг- и релиз-приложения разъедутся по данным (треки/туман пишутся раздельно) → Митигация: дебаг только для проверки жестов и съема логов, не для повседневного трекинга; в tasks есть явное предупреждение.
- [Риск] Временный код приживется → Митигация: все новое с префиксом `Dev`/`Diag`, задача на удаление `dev-logging` остается обязательной перед архивацией.

## Migration Plan

- Изменение обратно совместимо: tilt никому не обещан (спека требовала 0), дебаг-пакет ставится рядом, диагностика включается тем же тумблером.
- Откат: revert коммита возвращает жест и ветку возврата; батник продолжает собирать релиз как раньше.
- Проверка на устройстве: вертикальный свайп двумя пальцами (tilt 0, шторма нет), pinch 30 сек с `adb logcat | Select-String FogMap:`, дебаг-APK ставится рядом и отдает JSONL через `run-as`.

## Open Questions

- Нет открытых вопросов, меняющих спеку или подход. Порог 60 событий/сек — эвристика из одного замера; калибруется по новым логам без изменения спек (число — деталь реализации).
