# Design — add-region-borders

## Решения (зафиксированы в grilling-сессии)

1. **Слой**: полилинии Яндекс MapKit (`PolylineMapObject`), добавляемые в `mapWindow.map.mapObjects`
   на главном экране карты. Вуаль тумана (`FogMaskOverlay`) — Compose-слой поверх MapView, поэтому
   границы физически не могут оказаться поверх тумана: видимость «только в открытых участках»
   обеспечивается архитектурой, а не отдельной логикой обрезки. Compose-оверлей отклонён: он лёг бы
   поверх вуали, и границы пришлось бы вручную маскировать по туману.
2. **Полилинии, а не полигоны**: у `PolygonMapObject` нет штриха (`dashLength`), есть только заливка
   и обводка; заливка тонировала бы открытые дырки тумана. Заливка не нужна — под туманом видны
   только линии.
3. **Кольца**: рисуем каждый связный кусок (главное кольцо + кольца-отрезки), вложенные кольца
   (внутри главного — дырки/артефакты данных) пропускаем. Это же правило ложится в знаменатель
   площади: суммируются только не вложенные кольца. Незамкнутые кольца (`brest`, `vitebsk_oblast`,
   `belarus` и др.) явно замыкаются перед отрисовкой.
4. **Стиль по типам**: республика — жирная сплошная, область — штриховая, город — тонкая сплошная;
   единая палитра + `outlineColor/width` для читаемости на дневной и ночной карте. Конкретные
   цвета/толщины/dashLength — по скриншоту после реализации (владелец решит по картинке).
5. **Зум-гейт**: городские контуры скрываются при `camZoom < 10` (значение начальное, подлежит
   подстройке); области и республику не гейтим. `camZoom` уже есть в state, слушатель камеры на месте.
6. **Настройка**: новая секция «Карта» в `SettingsScreen`, один переключатель, `PrefsKeys` +
   DataStore Flow (по образцу `paused`/`diagEnabled`), default `false`. Границы действуют только на
   главной карте — история дня не затрагивается.
7. **Знаменатель процента**: площадь полигонов региона, вычисляемая в рантайме один раз (шалеус по
   не вложенным кольцам, 16 633 точки всего — доли мс). 13 констант `totalAreaKm2` удаляются.
   Полигоны и materialized counters в БД не трогаются (правка геометрии устарит накопленные счётчики,
   правка знаменателя действует мгновенно).
8. **Широтная поправка**: `area_per_cell = 0.000365 × cos²(широты)`; регион — центроид его колец,
   глобальные метрики — средняя широта Беларуси. Счётчики остаются целыми базовыми клетками, БД и
   миграции не меняются. Следствие: все отображаемые км² и проценты падают ~2,9× и становятся реальными.
9. **Достижения**: «100% региона» — при `percent >= 99` (полное открытие даёт ~98–102% из-за
   представительной широты); пороги 10/50% и 10/100/1000 км² не меняются; ранее полученные не отзываются.
10. **Проверки**: unit-тесты на эталонную площадь полигона, логику выбора колец и корректный процент
    при полном открытии. Instrumented-тест со снимком карты — нет (хрупкий, требует эмулятора).

## Технические заметки

- Объекты добавляются при включённом переключателе и прячутся `isVisible` (без пересоздания);
  порядок: сборка колец → фильтр вложенных → замыкание → `PolylineMapObject` со стилем типа →
  добавление/удаление по Flow настройки.
- Ширина линии в пикселях постоянна при текущем зуме (tilt зафиксирован в 0), пересчёт при смене
  зума не нужен; гейт городов — обновление `isVisible` из слушателя камеры.
- Порог `>= 99` и сравнение `percent >= p` живут в `AchievementChecker.regionPercent`/списке порогов.
- Глобальная средняя широта — константа рядом с `AREA_PER_BASE_CELL_KM2`, усреднённая по территории
  Беларуси (~53,7° с.ш.), комментарий с выводом.

## Risks / Trade-offs

- [Risk] **Точность границ**: полигоны упрощены Douglas-Peucker — максимальное отклонение замерено
  параллельным анализом: города ~25–45 м (допуск 0,0004°), области ~65–110 м (0,001°),
  республика ~130–221 м (0,002°). Граница на карте — «примерно так», для игрового тумана принято
  владельцем. Mitigation: зафиксировано здесь и в Risks аудита, пересоздание из OSM — вне скоупа.
- [Risk] **Данные колец неоднородны**: 4 региона содержат кольца-отрезки на удалении 1,5–14 км
  (Витебск 8,4 км², Гомель-город 4 шт, Минск 2 шт), у Минской области 6 колец лежат внутри Минска
  (дырки). Пропуск вложенных колец убирает ложные окружности, но если в данных появится настоящая
  дырка (напр. анклав), она не будет вычитана из площади. Mitigation: правило едино для отрисовки и
  площади, сценарий в спеке.
- [Risk] **Официальные площади больше не участвуют**: Минск-полигон на 16,5 км² (4,6%) больше
  официального 348,84 км², Могилёв-полигон на 2,4% меньше официального — теперь знаменатель следует
  за геометрией, поэтому в UI будут цифры, отличающиеся от Википедии. Mitigation: выбрано сознательно
  (единый источник правды, процент не уезжает >100%), разбор подозрительных колец — вне скоупа.
- [Risk] **Представительная широта**: расчётный процент при полном открытии ~98–102% (для крупных
  регионов отклонение средней широты клеток от центроида до ~±12%). Mitigation: допуск 99% для
  ачивки «100%», сценарий «Полное открытие региона» в спеке; точная метрика (сумма весов×cos² на
  инкременте) отклонена как требующая миграции БД и пересчёта из raw.
- [Risk] **Все числа в приложении упадут ~2,9×** (проценты регионов, «Площадь» в статистике и
  истории): пользователь может решить, что регресс. Mitigation: это и есть исправление; ачивки,
  уже разблокированные, сохраняются; CHANGELOG — в [Unreleased].
- [Risk] **Стиль по скриншоту**: цвета, толщины, dashLength и порог z10 выбраны как начальные и
  подлежат подгонке после того, как владелец увидит картинку. Mitigation: задача на подгонку в tasks,
  спеки фиксируют только наблюдаемые свойства («различимы», «читаемо», «ниже z10»).
- [Risk] **Количество объектов MapKit**: 13 регионов / 16 633 точки полилиний при включённом
  тумблере. Mitigation: добавление по требованию, прятанье через `isVisible`; лимиты viewport
  (см. mvp-foundation) для линий существенно мягче, чем для полигонов — проверить на устройстве.

## Migration Plan

Не требуется: БД, счётчики и достижения не меняются; константы площади удаляются в пользу рантайм-
расчёта; старые накопленные counters валидны как есть (единицы — базовые клетки, не км²).

## Open Questions

- Цвета, толщины, dashLength, точный порог скрытия городов — подгоняются по скриншоту при
  реализации (решение владельца по картинке).
