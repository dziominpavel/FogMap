## Context

См. `proposal.md` (Why) и дельта-спеки. Текущее состояние после `smooth-fog-zoom`: `FogMask.holesForZoom` возвращает `HolesResult(holes, mode)` с лесенкой точное -> z18 -> z16, гистерезис 600/800 в зоне >= 13 живет в `MapScreen`, грубые пятна (z16 и грубее) рисуются скруглением в четверть стороны, диагностика считает `fallback_hits`. Осталось: ниже 11 всегда z14 (две улицы выглядят как полгорода), первая ступень fallback x8, подушки слабые (на 13.x клетка z16 — ~20–30px, четверть дает те же 6px). Ограничения: горячий путь кадра, `MAX_HOLES=800` и пороги 13/11 не меняются.

## Goals / Non-Goals

**Goals:**
- Честная дальняя легенда: ниже 11 сначала z16, z14 — только при переборе.
- Мельче первая ступень near-fallback: z19 перед z18.
- Подушки вместо углов: половина стороны + шире перо.
- Видимость ступени в логе (`presence_z`).

**Non-Goals:**
- Не меняем `DETAIL_ZOOM`, `FAR_ZOOM`, `MAX_HOLES`, гистерезис near-зоны, пирамиду, компакшн, трекинг, `liveHoles`.
- Не вводим круглые пятна по клеткам и анимации перехода — следующая итерация при необходимости.

## Decisions

### 1. Дальняя лесенка: ниже 11 пробуем z16, затем z14
Ветка `zoom < FAR_ZOOM` строит пятна z16; при переборе — пятна z14 по обобщенному `fallbackHoles(z)`; перебор z14 — вуаль как раньше. Режимы `PRESENCE_Z16` / новый `PRESENCE_Z14`.
- Почему: тонкий маршрут в z16 дает десятки дырок против бюджета 800 (по логу дальних окон — единицы), а выглядит змейкой вместо кляксы; тяжелым пользователям с закрашенным городом цепочка сама падает на z14.
- Альтернатива (отклонена): сразу z15 как компромисс — лишний уровень без полевых данных; z16 уже проверена запасом.

### 2. Ступень z19 первой в near-цепочке
Порядок: точное -> z19 -> z18 -> z16, новый режим `PRESENCE_Z19`. Ранние выходы на каждом уровне ограничивают стоимость.
- Почему: прыжок x4 вместо x8 там где влезает; в сверхплотных вьюпортах z19 перебирает и падает дальше — поведение не хуже текущего.
- Альтернатива (отклонена): оставить z18 первой — дешевле на один merge, но пользователь explicitly просил мельче ступени.

### 3. Подушки: половина стороны и двойное перо
`COARSE_CORNER_FRAC` 0.25 -> 0.5, `COARSE_FEATHER_MULT` 1.5 -> 2.0. Точные дырки — без изменений.
- Почему: 0.25 на реальных пикселях 13.x неотличима от старых 6px; половина дает stadium-формы, ступени перестают читаться углами.
- Альтернатива (отклонена): круги по клеткам без merge — убивает лесенку полностью, но меняет число объектов на порядок и требует замера перфа; откладываем как следующий шаг если подушек не хватит.

### 4. `presence_z` в диагностике
`HolesResult` уже несет режим; `MapScreen` маппит режим в уровень и передает в `DevRenderStats`, агрегат `RENDER` пишет `presence_z` (0 — точное, без пятен). W-событий на уровень нет.
- Почему: следующий замер должен показывать какая ступень отрисовалась, иначе опять гадаем z19 vs z18 vs z16.
- Альтернатива (отклонена): эвристика уровня по числу дырок в разборе — врет на редких районах.

### 5. Гистерезис не расширяем на дальнюю лесенку
Флип z16/z14 на границе бюджета ниже 11 теоретически возможен, но обе ступени — грубая легенда (поп x4 между пятнами, не x32 с ниткой). Оставляем как есть, смотрим полевой лог.
- Почему: расширение stuck-механики на вторую зону усложняет слой ради мелкого визуального эффекта.
- Альтернатива (отклонена): обобщенный hysteresis для всех переходов — больше состояния в слое без доказанной нужды.

## Risks / Trade-offs

- [Длиннее цепочка merge] Худший кадр: оборванное точное + z19 + z18 + z16. Митигация: ранние выходы на 801 дырке; по логу merge 2–7 мс, запас есть; замер `avg_merge_ms` в приемке.
- [z16 внизу у тяжелых пользователей] Закрашенный город даст тысячи пятен z16. Митигация: цепочка падает на z14 — поведение как сейчас плюс один merge.
- [Подушки мылят] Половина стороны на крупных пятнах — почти эллипсы. Митигация: визуальная приемка на устройстве в обеих темах; откат констант одной строкой.
- [Тесты захардкодили режимы] `Mode` расширяется — существующие `assertEquals` режимов обновляются. Митигация: полный unit-suite в задаче.

## Migration Plan

Миграции БД и API нет. Откат — revert ченджа: дальняя ветка вернется на всегда-z14, near-цепочка на z18-первую, подушки на 0.25/1.5. Проверка: зум 10–11 над маршрутом (змейка z16), пан 13–14 (ступени мельче), `RENDER agg` (`presence_z` заполнено, `over_budget_hits = 0`).
