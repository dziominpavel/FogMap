## Why

Поездка по городу показала одновременно лишние и недостающие куски маршрута, а разбирать их нечем: текущая диагностика считает только отбросы без координат, STAND-статика и accuracy-дрейф выкидываются без следа, вердикты ворот C нигде не трейсятся. На dev-стадии без реальных пользователей нужен полный черный ящик полета и цикл калибровки трек + новый APK до идеала, плюс тем же механизмом перенос прогресса при переустановке.

## What Changes

- Бессрочный сырой лог всех Fused-фиксов до фильтров в новой таблице `raw_fixes` (каждый fix + вердикт фильтра + вердикт TrustEngine + исход ворот C + кисть/коридор).
- Батч-экспорт за период (диапазон дат от-до) в единый ZIP: `meta.json` (version + пороги + версия кода) + `days/*.jsonl` + snapshot `visited_cells` + `counters`. Share через системный chooser (Telegram), без варнингов.
- Батч-импорт из ZIP через системный picker: дни диапазона перезаписывают треки день-в-день, затем full rebuild всего тумана текущим кодом (лишнее пятно исчезает) и пересчет счетчиков с нуля в той же транзакции. Версия файла не блокирует импорт, raw всегда перепроживается текущим TrustEngine/PendingGate.
- Экран управления сырьем: в истории кнопка выгрузки диапазона + импорт, в хранилище список по дням (дата, точек raw, КБ) + удалить день / очистить все с объяснением: чистка сносит только raw, туман и треки остаются, пропадает только возможность экспорта/переноса.
- Проверка глазами на карте достаточна, отдельный diff-UI не делаем.

## Capabilities

### New Capabilities

- `track-debug`: сырой лог, батч-экспорт/импорт за период, full rebuild с пересчетом счетчиков, управление хранилищем raw.

### Modified Capabilities

(none — поведение `tracking`, `history`, `fog-grid`, `statistics` не меняется на уровне REQUIREMENTS; новый capability использует их как есть)

## Impact

- Код: `TrackingService` (запись raw синхронно в колбэке), новая `raw_fixes` таблица + DAO, `TrackRepository`/`FogRepository` (экспорт-билдер, импорт-rebuild), `HistoryScreens` (кнопки выгрузки/импорта диапазона), новый экран/секция хранилища, FileProvider Share как в `DiagScreens`.
- Данные: рост БД ~150КБ за 2 часа езды, ~1.5МБ за сутки непрерывки; ZIP переносим между установками.
- Совместимость: старые установки без raw не перепроживаются задним числом; туман монотонный инвариант сохраняется кроме явного импорта-rebuild.
