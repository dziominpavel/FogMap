# field-hardening

Полевое укрепление трекинга по разбору экспорта с P60 Pro (01.10–06.11).

Что показал разбор:
- процесс в foreground всё равно вытесняется: цикл записи тикал ~1 ч из 24, 35 `LIFE/freeze_gap` за сутки, максимум 2 ч 30 мин; по треку — ≈24 км провалов (5,7 %);
- пачка фиксов, отложенная заморозкой, приходила одним приёмом: 35 кандидатов → 1 принятая;
- `TRACK/day_branches` — 28,7 % файла (450 из 1 569), цель ≤ 20 %.

Изменения:
1. **Wake-lock движения** (`TrackingWake`): PARTIAL_WAKE_LOCK в ACTIVE/BURST, снятие в STANDBY и на паузе, освобождение в `onDestroy`, событие `TRACK/wakelock`.
2. **Агрегат `day_branches`** (`BranchLogGate`): событие не чаще 5 минут, пачки сводятся без потерь; `counters.json` не зависит от гейта.
3. **Метка приёма для отложенных фиксов** (`StaleReplay`): фикс старше 60 с, идущий вперёд по времени, получает `recv = loc.time`; счётчик уходит в `flush` полем `stale_replay`.

Решение владельца 2026-11-06: делать всё полевое укрепление одним change;
`proposal.md` и `design.md` не заводить — изменения описаны здесь.

Не входит: авторестарт после термостопа Huawei (система его не даёт) и
включение уведомлений на устройстве (действие владельца).
