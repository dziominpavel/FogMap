## Why

Rebuild дня 21.09 новым кодом (`История → Выгрузка → Импорт`) восстановил трек и туман (276 → 424 точки, `veto_stale` 17 → 0), но вскрыл три дефекта учёта: после импорта в дне нет эко-метрик вообще (`eco_fix=5` от одного живого flush, ключей префикса/разрывов/бакетов нет — `importAndRebuild` никогда не зовёт `recordEco`); `time_s` дня взлетел 2707 с → 38170 с, потому что rebuild режет чанки по 20 штук без ограничения по времени и чанк через дыру 09:16→12:25 вносит сразу 3 часа; а старый живой счётчик дистанции (19.59 км) не выводится из сохранённых точек (11.24 км строгим правилом) — признак двойного счёта при конкурентных `flush` (периодический 15 с + по размеру пачки).

## What Changes

- **Эко-метрики переживают импорт.** `importAndRebuild` SHALL восстанавливать эко-ключи (`fix/stand/gps_ms/flush/idle_burst/prefix/gap/бакеты`) из `counters.json` выгрузки за импортированные дни вместо пересчёта из прореженного raw (в STANDBY писалась каждая 6-я точка — пересчёт врал бы в меньшую сторону). Нет ключа в старом экспорте — 0; медиана без бакетов показывается как «нет данных», а не 0.
- **Чанки rebuild ограничены по времени.** Нарезка принятых точек: не больше 20 штук И спан чанка не больше ~120 с — разрыв режет чанк, тишина не впитывается в `time_s` дня.
- **Сериализация `flush`.** Параллельные запуски `flush` (таймер + переполнение буфера) SHALL NOT писать пересекающиеся батчи: мьютекс вокруг тела, best-effort пути (`onTaskRemoved`/`onDestroy`) при занятом мьютексе пропускают запись, а не виснут.
- Правило «снимок fog/counters из файла не используется» в `TrackDebugImport` SHALL сузиться до геометрии: туман/точки/дистанция/время/отбросы — пересчёт из raw, эко-метрики — восстановление из снимка.

### Modified Capabilities
- `tracking`: требование «Интервалы и фильтры точек» — сериализованный flush без двойного счёта; чанки rebuild ограничены по времени для честного `time_s`.
- `battery-eco`: требование «Метрики батареи и режим эксперимента» — эко-метрики восстанавливаются из выгрузки при импорте; медиана без данных помечается отсутствием данных.

## Impact

- Код: `data/TrackDebugImport.kt` (парсинг `counters.json`, восстановление эко-ключей, нарезка по времени), `tracking/TrackingService.kt` (мьютекс flush + best-effort пути), `data/TrackRepository.kt` (медиана «нет данных» — при необходимости), `ui/screens/HistoryScreens.kt` (подпись отсутствия данных — при необходимости).
- Спеки: 2 дельты (`tracking`, `battery-eco`); миграций БД нет (ключи counters уже есть).
- Тесты: `TrackDebugImportTest` (восстановление эко, нарезка по времени, толерантность к старым выгрузкам), существующие зелёные.
- Полевая проверка: повторный импорт дня 21.09 — эко-карточка совпадает с живой, `time_s` вменяемый; сверка счётчика дистанции с пересчётом из точек.
- Вне scope: борьба с заморозкой процесса на уровне ОС (только наблюдаемость есть), геометрия тумана, коридор > 500 м.
