## Context

См. `proposal.md` (Why) и `specs/map-render/spec.md`. Текущее состояние: `FogMask.holesForZoom` на `zoom >= DETAIL_ZOOM (13)` строит точные дырки всех уровней с ранним выходом при `> MAX_HOLES (800)`, `MapScreen` при `overBudget=true` отбрасывает все и рисует глухую вуаль. `FogRects.merge` на тонкой диагональной нитке почти не клеит (каждый ряд — отдельный run), поэтому в широком вьюпорте города (зум 13 + запас региона 25%) лимит превышается легко. Ограничения: горячий путь кадра (merge + `worldToScreen`), чистая логика `FogMask` покрыта unit-тестами, диагностика `RENDER over_budget` уже есть.

## Goals / Non-Goals

**Goals:**
- Убрать окно черного экрана 13–13,6: перебор точных дырок дает пятна z16, а не 0 дырок.
- Сохранить защиту от лагов: настоящий перебор (и пятна перебрали) — по-прежнему глухая вуаль.
- Сохранить fail-closed и тестовую структуру (чистая логика в `FogMask`).

**Non-Goals:**
- Не меняем значения `DETAIL_ZOOM`, `FAR_ZOOM`, `MAX_HOLES`, `MID_PRESENCE_Z` в этом чендже (тюнинг — отдельно по полевым логам).
- Не меняем пирамиду, компакшн, перо, `MIN_HOLE_PX`, проекцию `worldToScreen`.
- Не вводим промежуточные уровни агрегации (z18/z19) — только переиспользование существующей лестницы.

## Decisions

### 1. Fallback внутри `holesForZoom`, а не в `MapScreen`
В точной ветке (`zoom >= DETAIL_ZOOM`): при обнаружении перебора вернуть `presenceHoles(viewportCells, MID_PRESENCE_Z)` вместо усеченного списка точных дырок.
- Почему: `FogMask` — чистая логика без MapKit/Compose, покрыта `FogPyramidTest`; fallback остается unit-тестируемым. В `MapScreen` пришлось бы дублировать срез viewport и держать два источника правды.
- Альтернатива (отклонена): fallback в `MapScreen` по флагу `isOverBudget` — размазывает решение по UI-слою, усложняет тесты.

### 2. Порядок: точный merge с ранним выходом, затем один проход пятен
Сначала считается точный merge с существующим ранним выходом (`> MAX_HOLES` — стоп, полный список не досчитываем). Только при переборе считается `viewportCells` (переиспользовать уже посчитанный срез) + `presenceHoles(z16)`.
- Почему: в частом случае (влезаем в бюджет) нет двойной работы; второй merge запускается только в редком окне перебора.
- Альтернатива (отклонена): считать оба варианта всегда и выбирать — удваивает стоимость кадра на всех зумах >= 13.

### 3. Второй уровень защиты сохраняется
Если и пятна z16 превышают `MAX_HOLES`, возвращается их список как есть, `overBudget` остается true, `MapScreen` рисует глухую вуаль по существующей ветке.
- Почему: сохраняет требование «город целиком не тормозит» и не трогает UI-ветку глухой вуали.
- Альтернатива (отклонена): каскад z16 -> z14 при переборе пятен — добавляет новый визуальный уровень без полевых данных; отложить.

### 4. Диагностика без новой схемы лога
`DevRenderStats.onFrame` продолжает получать `overBudget=true` при срабатывании fallback, `holes` = число отрисованных пятен. Отдельного флага fallback в этом чендже нет.
- Почему: минимальная диффа, существующие дашборды и W-событие `slow_frame` продолжают работать; различие «fallback vs глухая вуаль» видно по `holes > 0` при `over_budget=true`.
- Компромисс: при разборе логов придется помнить эту семантику; если будет шумно — добавить `fallback=true` следующим ченджем.

## Risks / Trade-offs

- [Поп на границе 13 остается, но знакомый] Переключение точные -> пятна z16 видно глазом. Митигация: пятно z16 — тот же визуал, что на зуме 12.x, пользователь его уже видел; нового вида попа нет.
- [Двойной merge в кадре перебора] Кадр с перебором делает точный merge (оборванный) + merge пятен. Митигация: ранний выход обрывает первый проход на 801 дырке, второй проход работает с на порядок меньшим множеством предков.
- [Регион уже расширен на 25%] Срез viewport включает запас за краем экрана. Митигация: переиспользуем тот же срез для пятен — консистентность кадра важнее точной обрезки; сужение запаса — отдельно.
- [Не лечит причину роста числа дырок] Длинные диагональные треки по-прежнему дают много прямоугольников после merge. Митигация: вне скоупа; fallback делает симптом невидимым, оптимизация merge — следующим шагом по замерам `dt_merge_ms`.

## Migration Plan

Миграции нет (только локальный рендер, без схемы БД и API). Откат — revert ченджа, поведение вернется к глухой вуали в окне перебора. Проверка отката — ручной зум 12 -> 13 -> 14 над плотным районом + `RENDER agg`.
