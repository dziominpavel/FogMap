## Context

См. proposal.md (Why). Текущее состояние: два `Log.d("FogMask")` в `MapScreen` (прелоад и каждый кадр пересчета с `String.format` — спам и аллокации), логи `BootWorker`, материализованные счетчики отбросов/площади в Room. Нет: единого формата, session id, агрегации кадров, замеров памяти/jank, логов жестов и нажатий, файлового хранения, экрана диагностики. Главный подозреваемый — синхронный пересчет в `remember(cells, zoom, azimuth, target)` в UI-потоке на каждое событие `CameraListener` (включая tilt-возврат с анимацией) + `Offscreen` Canvas с 4 проходами на дырку + полный `observeCells()` список при каждом батче.

## Goals / Non-Goals

**Goals:**

- Дать склеиваемый таймлайн «жест → камера → пересчет → память → фриз» с одним форматом и session id.
- Уложиться в сотни КБ/день: агрегация кадров, запись файла на фоновом потоке, ноль аллокаций в горячем пути кроме аномалий.
- Разбор через `adb logcat -s FogMap:*` + pull файла, без бэкенда и без новых зависимостей по возможности.
- Временность: все точки интеграции помечены, удаление — одним change с revert.

**Non-Goals:**

- Не меняем логику рендера, трекинга, TrustEngine, PendingGate — только наблюдаем (допустимы наносекундные замеры вокруг существующих вызовов).
- Не строим графики/дашборды в приложении — только хвост 50 строк + Share.
- Не отправляем логи наружу автоматически — только ручной Share.
- Не покрываем детальным логом каждую GPS-точку построчно — только агрегаты flush и клетки `x,y,z21`.

## Decisions

- **Синглтон `DevLog` с кольцевым буфером (N=2000) + асинхронный file-writer.** Пишущий поток — один фоновый `HandlerThread`/корутин-канал; UI-поток только кладет событие в буфер (lock-free очередь) и возвращается. Альтернатива — писать файл синхронно: отвергнута, добавит jank в исследуемый код. Альтернатива — только logcat без файла: отвергнута, logcat теряется при смерти процесса и ротируется.
- **Ручной JSON без kotlinx.serialization, если ее нет в проекте.** Проверить `app/build.gradle.kts`; если сериализации нет — плоский `JSONObject`/ручная сборка строки (payload плоский, 1 уровень). Причина: не тащить зависимость ради временного кода.
- **Формат строки: `ts_wall|ts_mono|session|seq|tag|level|msg|payload_json`.** Разделитель `|` выбран потому что payload — JSON без переносов; парсинг одной строкой в Python (`split('|', 7)`). Альтернатива — чистый JSON на строку: отвергнута, длиннее и тяжелее читать в logcat глазами.
- **`session = UUID4` короткая (8 символов) + `startMono = SystemClock.elapsedRealtime()`.** `ts_mono = elapsedRealtime() - startMono`. Причина: переживает смену wall-clock, точна для jank-анализа.
- **Агрегаторы `CameraStats` и `RenderStats` с окном 2 сек.** Считают count, sum/max времен, последнее значение zoom/tilt, частоту событий. Сбрасываются по таймеру и пишут одно событие. Аномалии (кадр > 500 мс, `overBudget`, jank > 700 мс) идут мимо агрегатора сразу уровнем W. Причина: иначе pinch-жест даст сотни строк в секунду и сам станет причиной тормозов.
- **Замеры времени через `System.nanoTime()` вокруг трех точек в `MapScreen`:** `holesForZoom` (merge), цикл `worldToScreen`, суммарно; отрисовка — через `FrameMetrics`/ручной замер `onDraw` в `FogMaskOverlay` (только длительность, без аллокаций). Альтернатива — systrace/Perfetto: оставить как второй инструмент, не замена (нужен именно коррелированный лог).
- **Память/jank: `Runtime.totalMemory/freeMemory` + `ActivityManager.getMemoryInfo` в агрегате `PERF` раз в ~10 сек + `Choreographer.FrameCallback` для детекта пропущенных кадров.** ANR-сторож — отдельный поток с heartbeat: если UI-поток не отвечает 5 сек — W-событие. Причина: штатного колбэка ANR без смерти процесса нет, сторож — стандартный прием для временного лога.
- **Интеграция в `CameraListener`: только счетчики + последнее значение, без строк.** Строка собирается в агрегаторе на фоновом потоке. Tilt-события считаются отдельно (`tiltFixCount`), чтобы увидеть петлю возврата.
- **Хранение: `context.cacheDir/logs/fog-YYYYMMDD.jsonl`, append, ротация по дате, чистка > 24 ч в `FogMapApp.onCreate` на фоновом потоке.** `cacheDir` выбран потому что это временные данные (система может чистить) + не нужен permission. Тумблер — новый `PrefsKeys.DIAG_ENABLED` в DataStore, по умолчанию true.
- **Экран «Диагностика»: read-only хвост из кольцевого буфера (StateFlow последних 50) + Share через `FileProvider` + «Очистить».** Пункт входа — Настройки (временная секция) + отдельный route `diagnostics`. Причина: в поле нет adb, нужен способ убедиться что лог пишется и забрать файл.

## Risks / Trade-offs

- [Риск] Сам лог тормозит исследуемый код → Митигация: агрегация, запись на фоновом потоке, запрет `String.format` в горячем пути, замер оверхеда (событие `PERF` с `logQueueDepth`).
- [Риск] Потеря событий при убийстве процесса (буфер не сброшен) → Митигация: сброс очереди при `onTaskRemoved`/`onDestroy` best-effort с таймаутом 1 сек; потеря хвоста < 1 сек приемлема, смерть видна по смене `session`.
- [Риск] Файл растет при долгих жестах → Митигация: агрегаты 2 сек + лимит файла 2 МБ (после — дроп с событием `log_rotated`, fail-safe вместо падения).
- [Риск] Координаты утекут в лог → Митигация: ревью-правило «payload без lat/lon», только `x,y,z21`; валидационный тест grep по `lat`/`lon` в DevLog вызовах.
- [Риск] Временный код приживется навсегда → Митигация: все классы/экраны с префиксом `Dev`/`Diag`, задача «удалить dev-logging» как обязательный пункт перед архивацией change.
