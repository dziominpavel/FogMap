## Context

См. `proposal.md` (Why). Текущее состояние: `versionCode = 2` и `versionName = "0.2.0-mvp"` захардкожены в `app/build.gradle.kts:39-44`; `BUILD_TIME` генерируется при конфигурации; `build-apk.bat:81-86` именует APK только по дате; «О программе» показывает `versionName` + `BUILD_TIME` (`SettingsScreen.kt:178-182`). Ограничения: только русский, только portrait, раздача прямым APK, две рабочие машины + CI, частые грязные локальные сборки, `*.apk` в `.gitignore`.

## Goals / Non-Goals

**Goals:**
- Детерминированная версия без файла-счетчика: один и тот же коммит всегда дает один и тот же `versionCode`.
- Каждый грязный билд визуально отличим везде: имя файла, консоль установки, «О программе».
- Монотонный `versionCode` для установки поверх без сноса.

**Non-Goals:**
- Публикация в Play Store и сложности канареек/стадий — вне скоупа.
- Автобамп базовой версии и ченджлог — руками.
- Подпись и кейстор не меняются.

## Decisions

- **База в файле `version` в корне, содержимое `1.0.0` в одну строку.** Альтернатива — `gradle.properties` или хардкод: отвергнуто, отдельный файл проще читать скриптам и человеку, легко проверять в CI. Бамп только руками.
- **Без файла-счетчика; `versionCode = git rev-list --count HEAD`.** Альтернатива A (коммитимый счетчик): отвергнута — каждая сборка на двух ПК дает конфликт мержа одной строки. Альтернатива B (локальный счетчик): отвергнута — дубли номеров, даунгрейд режется Android. Commit-count детерминирован и не требует синхронизации. Защита: `max(count, 3)` на случай пустой истории, чтобы гарантированно превзойти текущий `2`.
- **Формат `versionName = <base>.<count>-g<sha>[-dirty-<TS>]`.** `sha` — `git rev-parse --short HEAD`, `TS` — `yyyyMMdd-HHmm` времени конфигурации, только в грязной ветке. Чистый билд стабилен и воспроизводим; грязный всегда уникален глазом даже без коммита. Суффикс `-mvp` убран по решению владельца (база `1.0.0`).
- **Вычисление в Gradle через провайдеры с фолбэками, без падения сборки.** `version` читается из файла (нет файла — `0.0.0-dev`); git-команды выполняются через `providers.exec`, при отсутствии git/CI-shallow — `count=0`, `sha=unknown`, сборка помечается dirty с меткой времени. Инкремента при sync нет в принципе — значение функция состояния репо, а не счетчик.
- **Новые `BuildConfig`-поля: `FULL_VERSION`, `GIT_SHA`, `GIT_COUNT`, `GIT_DIRTY` (+ существующие `VERSION_NAME`, `BUILD_TIME`).** UI форматирует из них строку, а не парсит `versionName` — так грязная метка и sha доступны отдельно для будущих нужд (например, экспорт `meta.json` в track-debug).
- **`build-apk.bat`: имя `FogMap-<fullVersion>-<mode>.apk`, `latest` как копия.** `fullVersion` получается из Gradle одним вызовом задачи-помощника (например, `printFullVersion`), а не дублированием логики в bat. Перед `adb install` — echo версии; после — сверка `adb shell dumpsys package ru.fogmap | findstr versionName` (release) или `ru.fogmap.dev` (debug).
- **Debug использует ту же схему.** Пакет отличается суффиксом `.dev`, коллизий с release нет, а видимость билда при дебаге даже важнее.

## Risks / Trade-offs

- [Risk] Shallow clone в CI дает неверный count → Mitigation: в `ci.yml` `fetch-depth: 0`; при невозможности — фолбэк с явной dirty-меткой, такой APK не раздавать как релиз.
- [Risk] Rebase/переписывание истории меняет count немонотонно → Mitigation: для прямой раздачи приемлемо; документировать, что базой порядка для телефона является `versionCode` конкретного артефакта, а не дата.
- [Risk] `git status --porcelain` медленный/шумный на больших деревьях → Mitigation: вызывается раз при конфигурации, untracked-игнор не нужен — любой вывод считается dirty, это консервативно и правильно.
- [Risk] Windows-батник и кодировки при чтении версии → Mitigation: файл `version` — ASCII в одну строку без BOM; чтение в Gradle через `readText().trim()`, в bat — только готовое имя от Gradle.
- [Risk] Локальные сборки без git (zip-исходники) → Mitigation: фолбэк `0.0.0-dev-unknown-dirty-<TS>`, в «О программе» видно, что это не релизный билд.

## Migration Plan

- Добавить `version` с `1.0.0`, применить схему, собрать release, проверить установку поверх текущего `versionCode=2` (ожидается `count HEAD` > 2).
- Переименовать выходные APK по новой схеме; старые файлы в `dist/archive/` не трогаем.
- Откат: удалить `version` и вернуть хардкод `versionCode`/`versionName` — телефон продолжит обновляться только если вернуть код не ниже установленного.
