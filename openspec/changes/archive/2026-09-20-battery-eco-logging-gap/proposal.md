## Why

Для одиночного полевого теста (один телефон, без A/B сборок) файл диагностики `fog-YYYYMMDD.jsonl` — единственный источник правды о сне/пробуждениях. Сейчас в нем не хватает двух сигналов: счетчиков fix/STAND за flush и причины пробуждения (дистанция/вердикт). Без них JSONL в одиночку несравним с треком — приходится дотягивать данные из `counters.json` и гадать о причине wake.

## What Changes

- Событие `TRACK/flush` (и `slow_flush`) дополнительно несет эко-снимок пачки: число фиксов, число STAND, GPS-время профиля с прошлого flush.
- Событие `TRACK/eco_state` дополнительно несет причину перехода: предыдущий профиль, дистанция до якоря в метрах (целое, без координат), вердикт TrustEngine.
- Поведение трекинга, профили, пороги, БД и разрешения не меняются — только состав payload логов.

## Capabilities

### New Capabilities

- Нет новых возможностей.

### Modified Capabilities

- `battery-eco`: требование «Метрики батареи и режим эксперимента» уточняется — какие поля несут `flush` и `eco_state`, чтобы один JSONL был самодостаточен для сверки с треком.

## Impact

- Затрагивает только `TrackingService` (состав `DevLog` payload, без смены логики переходов) и один unit-тест формата payload.
- Новых разрешений, миграций БД, изменений UI и расхода батареи нет (2–3 числа на flush).
- Координаты в лог по-прежнему не попадают — только метры и счетчики.
