## Goals / Non-Goals

**Goals:**
- Архитектура одного модуля, покрывающая 6 спек change
  (fog-grid, map-render, tracking, statistics, history, app-shell).
- Схема БД Room и поток данных «точка → ячейки → слой → счетчики».
- Подход к рендеру тумана, не нарушающий атрибуцию Яндекса.

**Non-Goals:**
- Импорт/экспорт (этап после MVP), офлайн-карты, мультимодульность, CI.

## Decisions

### Один app-модуль, пакеты по фичам, ручной DI
`app` с пакетами `fog`, `map`, `tracking`, `stats`, `history`, `settings`,
`onboarding`, `data`. Зависимости собираются вручную (AppContainer),
без Hilt/Koin — проще для соло-проекта; слои data/domain/ui внутри пакетов.
Альтернатива (мультимодуль/Hilt) отвергнута как избыточная для MVP.

### Сетка: WebMercator 100 м, ID = пара (x, y) на фикс-зуме
ID ячейки — целочисленная пара тайловых координат на зуме, где клетка ≈100 м.
Храним только открытые ячейки (`visited_cells(x, y)`, составной PK + индекс).
Радиус открытия — круг ячеек вокруг точки по порогам скорости 100/200/500 м.
Альтернатива (H3/S2, переменный размер) отвергнута в `decisions.md`:
ломает ID/площадь/рендер.

### БД Room: 3 таблицы + счетчики
- `visited_cells(x INTEGER, y INTEGER)` — PK (x, y).
- `tracks(id, started_at, finished_at, distance_m, points_count, name)`.
- `track_points(track_id, time, lat, lon, acc, speed)` — индекс по track_id.
- `counters(key, value)` — площадь (в ячейках), дистанция, время, кол-во треков
  + разрезы день/неделя (ключи с датой). Миграции с версии 1, без шифрования.
  Запись точек — пачками транзакцией; открытие ячеек и инкремент счетчиков —
  в той же транзакции (атомарность «точка → туман → статистика»).

### Рендер: полигоны MapKit по viewport
Слой тумана — `PolygonMapObject` из MapKit: на каждое обновление карты строим
покрытие видимой области неоткрытыми клетками со склейкой соседних в
прямоугольники, LRU-кэш склеенных геометрий; на мелких зумах — агрегация.
Полигоны — объекты карты, поэтому логотип/копирайты SDK остаются поверх
(требование map-render). Альтернатива (полноэкранный Canvas-MASK) отвергнута:
нагрузка на CPU/GPU + риск перекрыть атрибуцию.

### Трекинг: ForegroundService + Fused, Flow-пайплайн
`TrackingService` (type=location) → FusedLocationProvider (5–10 сек / 10–20 м)
→ фильтры (accuracy, скорость, mock) → батч-буфер → Room-транзакция →
обновление слоя и счетчиков через Flow. Пауза — флаг в DataStore,
авторестарт — BroadcastReceiver на BOOT_COMPLETED. Уведомление стандартное
с действием паузы.

## Risks / Trade-offs

- [Risk] Лимит полигонов MapKit на широких viewport → Mitigation: склейка +
  агрегация на мелких зумах; проверить на эмуляторе первым делом (задача в tasks).
- [Risk] Doze/китайские прошивки убивают сервис → Mitigation: онбординг батареи
  + ForegroundService; идеальной доставки нет, принято.
- [Risk] Точность площади (0,01 км² без учета широты) → Mitigation: принято
  как достаточное для MVP, зафиксировано в спеке.
- [Risk] MapKit Full тяжелее Lite → Mitigation: принято владельцем с запасом;
  пользователей ≤50, размер APK некритичен.
