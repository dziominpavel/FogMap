## Context

Текущая архитектура: полностью офлайн-first, бэкенда нет. Достижения и региональный прогресс — локальные. Мотивация — proposal.md. Зависимости: `add-region-progress`, `add-achievements`. Приватность из vision: «ничего никуда не отправляем» — этот change меняет политику осознанно.

## Goals / Non-Goals

**Goals:**
- Список друзей (локально + сервер)
- Ежедневный снимок прогресса (регионы + achievements)
- Экран профиля друга (усечённый)
- Базовая настройка приватности

**Non-Goals:**
- Real-time обновления
- Чат/сообщения
- Глобальный leaderboard
- Публикация точек/tracks (только агрегаты)
- Сложная аутентификация (достаточно простого токена)

## Decisions

**1. Бэкенд: минимальный API**
- Решение: простой REST API (Hono/Node/Go) + SQLite на сервере. Эндпоинты: `POST /snapshot`, `GET /snapshot/{userId}`, `POST /friends`, `GET /friends`.
- Альтернатива: Firebase — vendor lock-in, сложнее локальная разработка.
- Хостинг: VPS/внутренний сервер владельца (масштаб ~50 пользователей).

**2. Аутентификация: токен при первом запуске**
- Решение: генерация device-id + токена при первом синке, привязка к «приглашению» (код друга).
- Альтернатива: email/пароль — избыточно для 50 пользователей.

**3. Снимок прогресса: что публикуется**
- Решение: JSON `{regions: {id: {cells, percent}}, achievements: [id], updatedAt}`.
- Не публикуется: tracks, points, raw fixes, точные координаты.

**4. Синк: WorkManager (exact daily)**
- Решение: `PeriodicWorkRequest` 24ч, экспоненциальный retry при офлайне.
- Альтернатива: AlarmManager — сложнее, не нужна точность до минуты.

**5. Хранение друзей: Room + сервер**
- Решение: таблица `friends` (userId, displayName, lastSnapshot) локально; сервер хранит связи.

**6. UI: отдельный раздел**
- Решение: новый пункт навигации «Друзья» (или внутри Achievements). Экран друга — карточки регионов + achievements (без карты).

## Risks / Trade-offs

- [Нарушение offline-first] → Синк опционален; при отсутствии сети всё работает локально.
- [Приватность] → Минимальный снимок по умолчанию; явные настройки.
- [Бэкенд как single point of failure] → Локальный прогресс не зависит от сервера.
- [Взлом/утечка агрегатов] → Нет чувствительных данных (только % и ids).

## Migration Plan

1. Спроектировать API + развернуть сервер (отдельный репо).
2. Добавить Room-таблицы `friends`, `user_snapshots`.
3. WorkManager для синка.
4. UI: навигация + экраны.
5. Rollback: отключить синк, данные локально остаются.

## Open Questions

- Нужна ли модерация/блокировка друзей? — вероятно, нет на старте (50 пользователей, знакомые).
- Срок хранения снимков на сервере? — предложение: 90 дней, потом агрегировать.
